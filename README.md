# PTT 發文稿酬（P 幣）計算器

**[▶ 開啟計算器](https://dube116.github.io/ptt-money-calculator/)**

貼上文章即時估算發文可獲得的 P 幣，並標出哪些內容有計分、哪些被去重或排除。
依 2026/10/22 之後的**現行版本**推測規則計算，**非官方公式**，站方可能隨時調整。

---

## 1. 背景

2026/10 PTT 改版發文稿酬：不再看游標移動或按鍵間隔，只看內容。
GitHub 上 [pttbbs](https://github.com/ptt/pttbbs) 的 `calc_post_entropy()` 是預設實作（計有效字元的位元組數），
站上實際使用的版本不同且不公開（函式宣告為 `GCC_WEAK`，可由站方覆蓋）。

本計算器的規則，是以實際文章的稿酬（BBS 文章資訊 `Q` 顯示的價格）配合 ptt.cc 上的全文反推而得。

## 2. 推測規則（現行版本）

```
詞元   = 每個非 ASCII 字元（中文、全形標點、日文假名…）→ 2 分
         含字母的英數串（可含 _）→ 每字元 1 分，每詞最多 8 分；去重看完整的詞
         純數字、半形符號、色碼控制碼 → 不算
分數   = 每個不同詞元最多算 2 次
不計入 = 引用行（: 開頭）、所有 ※ 開頭的行（含看板發文提醒範本）、
         內文第一個單獨 -- 行之後（簽名檔）、網址
基本   = 分數 < 40 → 0P；否則 floor(分數 × 0.08)，上限 150P
遞減   = 基本 − 3 × 當天（0:00 起）在這篇之前已拿到稿酬的篇數，最低 1P
最後   = [新聞] 最多 5P、[情報] 最多 30P（回文不受限）；Fw: 轉錄 0P
```

當日篇數只計「有拿到稿酬」的文章：原始碼中 `StatIncDailyPost()` 位於 `if (money > 0)` 之內。

## 3. 驗證

| 項目 | 樣本 | 完全命中 |
|---|---|---|
| 基本公式（作者當天首篇、無色碼） | 410 | 404 |
| 基本公式（有色碼文章） | 389 | 351 |
| 當日遞減（10/23） | 128 | 107 |

未命中的文章，誤差型態都符合兩種無法從外部觀察的因素：

- **看不到的前文**：作者當天被刪除的文章仍計入篇數 → 實拿比預測少，且差距為每篇扣的 P 數的倍數。
- **舊版連線**：PTT 更新程式後，已登入的連線會沿用舊版直到重新登入。改版前登入、一直沒登出的連線，
  發文會套用舊版算法（例如純數字也算分），且不計入新版的當日篇數。

被否定的假設（均顯著降低命中率）：純數字計分、網址任何部分計分、半形符號計分、色碼控制碼切詞、
上色文字不計分、分段/滑動視窗去重、四捨五入或兩段取整、以滾動 24 小時計算當日篇數。

## 4. 規則演變（觀察到的版本）

| 期間 | 當日遞減 | 基本公式 |
|---|---|---|
| 10/21 改版初期 | 不扣 | 較寬鬆（純數字也算分） |
| 10/22 白天 | 每篇 −1P | 現行 |
| 10/22 深夜起 | 每篇 −3P | 現行 |

## 5. 檔案

- `index.html`：頁面
- `calc.js`：計算核心（瀏覽器與 Node.js 共用）

頁面零外部載入資源，可離線使用；草稿只存在瀏覽器的 localStorage。
